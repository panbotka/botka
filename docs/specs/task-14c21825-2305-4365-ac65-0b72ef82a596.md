# Auto-summarize task failures

When a task fails, produce a short LLM-generated summary of why so users don't have to read full logs.

## Requirements

- Add `failure_summary` (text, nullable) column to `tasks`.
- After a task transitions to `failed` (or `error`), the runner submits the last ~200 lines of task output plus the spec to a small Claude call (haiku model) asking for a 2-4 sentence root-cause summary in Czech.
- Summary generation runs asynchronously; failure to generate (API error, timeout) leaves the column null and logs a warning — never blocks the failure transition itself.
- Task detail page renders the summary in a highlighted box at the top of the failed task view, with a "Regenerate" button that re-runs the summarization.
- Task list view shows the first sentence of the summary as a tooltip on the failed status badge.
- Add config var `FAILURE_SUMMARY_ENABLED` (default true) and `FAILURE_SUMMARY_MODEL` (default `haiku`).

## Implementation Notes

- Reuse the existing Claude Code spawn logic — call `claude -p` with `--output-format json` for a single non-interactive turn rather than building a separate Anthropic SDK client.
