# Bulk operations on tasks

Allow selecting multiple tasks in the UI and performing one operation on all of them at once.

## Background

Operating on tasks today is one-at-a-time. When triaging dozens of failed tasks or queueing a batch of pending ones, this is tedious. Bulk operations should cover the common verbs.

## Requirements

- HTTP API: add `POST /api/v1/tasks/bulk` accepting:
  - `task_ids`: array of UUIDs (required, max 100 per call)
  - `operation`: one of `cancel`, `requeue`, `delete`, `set_priority`, `set_pending`, `add_tags`, `remove_tags`
  - `payload`: operation-specific (e.g. `{"priority": 5}` for `set_priority`, `{"tag_ids": [1,2]}` for tag ops)
- Response: `{"data": {"succeeded": [ids], "failed": [{"id": "...", "error": "..."}]}}` — partial success is OK; per-task validation failures (e.g. invalid status transition) are reported per-id, not as a whole-request error.
- All bulk operations respect the same status-transition validation as single-task updates.
- Wrap each task's mutation in its own transaction so one failure does not roll back the whole batch.
- Frontend:
  - Add checkbox column to the task list (header checkbox = select all visible).
  - When ≥1 task is selected, show a sticky action bar with: Cancel / Requeue / Delete / Set priority / Move to pending / Add tags / Remove tags.
  - Show a confirmation dialog before destructive ops (delete) summarizing the count.
  - After bulk op, show a toast with succeeded/failed counts; clicking the toast opens a panel listing per-task failures.
- MCP: add `bulk_update_tasks` tool exposing the same operations.

## Implementation Notes

- The `add_tags` / `remove_tags` operations depend on the tags feature (separate task) — implement defensively so this task can land independently if tags exist by then; otherwise gate those two operations behind a feature check.
- Use `db.Transaction` per task; do not use a single big transaction (long lock + all-or-nothing semantics are wrong for triage workflows).
- Cap at 100 IDs per request to bound execution time.
