# Keepalive: skip ping when there was recent activity

When a task was recently launched or a chat message was sent, the 5h window is already kept alive by that real activity. The hourly keepalive ping is redundant in those cases and just burns tokens. Make the ping skip itself when the system has been active recently.

## Requirements

- In `internal/runner/keepalive.go`, modify `keepalivePing()` to skip the ping when there has been activity in the last 50 minutes (slightly less than the default 60m interval, so a quiet hour still produces a ping).
- "Activity" means either: the most recent `tasks.started_at` or the most recent `messages.created_at` is within the threshold. Take the max of those two.
- The threshold must be configurable via a new env var `KEEPALIVE_ACTIVITY_THRESHOLD` (Go duration, default `50m`). Add it to `internal/config/config.go` and document it in `CLAUDE.md`, `README.md`, and `.env.example`.
- When a ping is skipped due to recent activity, log it at info level with the reason and the age of the most recent activity (e.g. `keepalive skipped: recent activity 12m ago`).
- Existing skip-when-stopped behavior must be preserved.
- DB queries must be lightweight — use indexed columns and `LIMIT 1`. If the DB is unavailable or the queries fail, log a warning and fall through to pinging (fail open — better to ping unnecessarily than to let the window expire).
- Add unit tests in `internal/runner/keepalive_test.go` covering: skip when recent task, skip when recent message, ping when both are old, ping when DB error occurs, and ping when both tables are empty.

## Implementation Notes

- The Runner already has access to the GORM DB via `r.db`. Add a helper like `mostRecentActivity() (time.Time, error)` that returns the max of the two timestamps.
- Existing tests use `pingFn` injection — keep that pattern. The new activity check should happen *before* `doPing()` is called.
- Keep the implementation small. This is a pre-flight check, not a redesign of the keepalive loop.
