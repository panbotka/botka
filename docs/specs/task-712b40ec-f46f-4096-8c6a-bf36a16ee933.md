# Task tags/labels with colors

Allow tagging tasks with one or more colored labels for visual categorization and filtering.

## Background

Tasks currently have only `title`, `project`, `priority`, and `status`. There is no way to categorize tasks by type (bug, feature, refactor, chore, infra) or any other dimension. As the task list grows, finding related work becomes hard.

## Requirements

- Add a new `task_tags` table: `id` (bigserial), `name` (unique, case-insensitive), `color` (hex string, e.g. `#FF5733`), `created_at`.
- Add a many-to-many join table `task_tag_assignments`: `task_id` (uuid), `tag_id` (bigint), composite PK.
- HTTP API:
  - `GET /api/v1/tags` — list all tags
  - `POST /api/v1/tags` — create a tag (`name`, `color`)
  - `PATCH /api/v1/tags/:id` — rename or recolor
  - `DELETE /api/v1/tags/:id` — delete tag (cascade-removes assignments)
  - `POST /api/v1/tasks/:id/tags` — assign one or more tag IDs to a task (replace semantics)
- Extend `GET /api/v1/tasks` with `?tag_id=N` (repeatable) filter — return tasks having ALL specified tags.
- Extend task list response to include `tags` array per task.
- MCP tool `list_tasks` accepts optional `tag_names` array filter.
- Frontend:
  - Show colored chips on each task row (task list + task detail).
  - Tag picker in task detail (multi-select, with create-new option).
  - Filter bar in task list: chips that toggle filtering.
- Migration: include 5-6 default tags seeded (bug, feature, refactor, chore, infra, docs) with sensible colors.

## Implementation Notes

- Reuse the chat tag pattern from Chatovadlo — `internal/models` already has a `Tag` model for threads. Mirror that structure.
- Color validation: must match `^#[0-9A-Fa-f]{6}$`.
- Soft-delete is unnecessary here; tags are user-managed and rare to recover.
