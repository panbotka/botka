# Declutter the mobile chat header and composer

The chat is used mainly on a phone (iOS PWA). The mobile chat header in `frontend/src/pages/ChatPage.tsx` (mobile branch) crams a back arrow, command-palette button, fork badges, `ProjectPicker`, `CommandButtons`, a model label and a settings gear into one row, and `BookmarksBar` gets its own extra row below. The model is shown but can only be changed inside `ThreadSettingsPanel`, a full-screen overlay. The composer (`frontend/src/components/ChatInput.tsx`) adds quick chips New chat / Search / Clear history that duplicate the command palette and slash commands.

## Requirements

### Mobile header (one row, no second row)
- Left: back arrow. Then the thread title (truncated); tapping the title opens the thread settings.
- Right: a compact model chip (e.g. "opus") — tapping opens a small popover/sheet listing the available models (same list and same save logic as the model picker in `ThreadSettingsPanel`); choosing one switches the model immediately.
- Right: fork badges / Box-running indicator stay only if active, as small icons.
- Right: a "⋯" button opening a bottom sheet with: Project (opens project picker), Commands (the `CommandButtons` actions), Command palette, Bookmarks (list from `BookmarksBar`), Thread settings, plus New chat, Search in thread, Clear history.
- Remove the separate `BookmarksBar` row on mobile.

### Thread settings on mobile
- On mobile, `ThreadSettingsPanel` opens as a bottom sheet (slides up, max ~85% height, scrollable, drag handle, backdrop tap closes) instead of the full overlay. Desktop stays as is.

### Composer
- Remove the New chat / Search / Clear history quick chips from the composer on mobile (they are now in "⋯" and remain in the palette and slash commands). On desktop they may stay.
- Keep the plan/act toggle, but render it as a small icon toggle next to the attach button on mobile.
- The token/cost context bar above the composer becomes a single thin muted line on mobile (or hidden behind a tap), not a full bar.

### General
- All tap targets ≥ 44px. Keep the existing `lvh` / in-flow bottom-nav rules from CLAUDE.md intact.
- Desktop layout is unchanged except where shared components are touched.

## Implementation Notes
Reuse an existing bottom-sheet component if the codebase has one; otherwise create a small reusable `BottomSheet` component. Add Vitest tests for the "⋯" sheet contents and the model chip switching. `make check` must pass.
