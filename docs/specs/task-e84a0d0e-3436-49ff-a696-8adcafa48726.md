# Per-chat skill enable/disable with skill registry and default flag

Let users turn Claude Code skills on/off per chat, backed by a Botka-managed
skill registry. Each skill has a `default_enabled` flag; a new chat starts with
exactly the skills whose default is on.

## Mechanism (verified)

- Claude Code supports denying specific skills per session via
  `--disallowedTools "Skill(name-a) Skill(name-b)"` (the `Skill(<name>)`
  permission specifier exists in the CLI). There is no positive allowlist for
  skills, so enforcement is subtractive: pass a deny entry for every skill that
  is OFF for the chat.

## Data model

- New `skills` registry table: `name` (unique slug), `description`, `source`
  (user / project / plugin:<name>), `default_enabled` (bool, defaults to true
  for newly discovered skills so current behavior is preserved), timestamps.
- Per-thread overrides: `thread_skills` (thread_id, skill_name, enabled).
- Effective state for a thread/skill = the `thread_skills` override if a row
  exists, else the skill's current `default_enabled`. A brand-new chat has no
  overrides, so it inherits all default-on skills automatically.

## Registry sync

- Scan skill sources and upsert into `skills`: global `~/.claude/skills/*/SKILL.md`,
  project `.claude/skills/`, and plugin skills under `~/.claude/plugins`. Parse
  each `SKILL.md` frontmatter for `name` and `description`.
- Sync on server startup and expose a manual "rescan" endpoint. Skills that
  disappear from disk should be marked/removed without dropping user overrides
  for still-present skills.

## Enforcement

- In BOTH spawn paths (`internal/claude/pool.go` and `internal/claude/runner.go`),
  compute `disabled = allKnownSkills - effectiveEnabled(thread)` and append
  `--disallowedTools "Skill(x) Skill(y) ..."` when the disabled set is non-empty.
- Session pool: pre-warmed processes bake args at spawn, so changing a thread's
  skill toggles must evict the pooled session for that thread — reuse the existing
  eviction pattern used on model/project change.

## API

- `GET /api/v1/skills` — registry with `default_enabled`.
- `PATCH /api/v1/skills/:name` — set `default_enabled`.
- `POST /api/v1/skills/rescan` — re-sync registry from disk.
- `GET /api/v1/threads/:id/skills` — effective per-chat state.
- `PUT /api/v1/threads/:id/skills` — set per-chat overrides.

## UI

- Global skill management view: list skills with description + source and a
  `default_enabled` toggle per skill, plus a rescan button.
- Per-chat skill panel (near the model selector): toggle skills for the current
  thread; persists as overrides and takes effect on the next message.

## Acceptance

- A skill toggled OFF for a chat is not invokable in that chat (denied), while
  still available in other chats where it is on.
- Creating a new chat enables exactly the default-on skills.
- Changing a skill's `default_enabled` affects new chats (and any chat with no
  explicit override) but not chats that have an explicit override.
- Follow the golang-developer skill conventions; add tests for registry sync,
  effective-state resolution, and deny-arg construction. `make check` must pass.
