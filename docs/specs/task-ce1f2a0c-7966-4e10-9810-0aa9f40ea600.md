
# Unified Search Results in Sidebar

The sidebar search in `frontend/src/components/ThreadSidebar.tsx` currently displays only thread results (with optional message snippets). It does not group results by type and does not show projects, tags, or personas matched. Users can't easily find a thread by tag name or jump to related entities. Reuse the global-search backend response, group results by category, and let the user click any category match to navigate.

## Requirements

- Replace the current sidebar search call (`searchMessages(q)`) with the global search call (`globalSearch(q)`) — the response shape is `GlobalSearchResults` with `threads`, `tasks`, `projects`, `messages` arrays.
- Render results in the sidebar as a single scrollable list with section headers (small uppercase, `text-zinc-400`):
  1. **Threads** — title-matched threads. Click navigates to `/chat/<id>`.
  2. **Messages** — body-matched messages. Render the snippet (HTML with highlight `<mark>` tags from backend) under each item. Click navigates to `/chat/<thread_id>` and (if practical) jumps to the matched message; if jumping is not trivial, just navigate to the thread.
  3. **Projects** — project matches. Click navigates to `/projects/<id>`.
  4. **Tasks** — task matches. Click navigates to `/tasks/<id>`.
- Each section appears only if it has results. If all sections are empty, show "No results found" (existing string).
- Keep the 300ms debounce and 2-character minimum already in place.
- Keep the loading state ("Searching...") and the existing search input UI (search icon, clear X, escape-to-clear).
- When the search input is empty (less than 2 chars), revert to the normal thread list view (existing behaviour).

## UI Details

- Section headers: same style as existing "Pinned" / "Archived" headers in the file (`px-3 py-1.5 text-[11px] font-medium text-zinc-400 uppercase tracking-wider`).
- Result rows: same padding/hover style as existing thread rows. For messages, render the snippet as HTML (the backend returns highlighted `<mark>` tags — currently rendered via `dangerouslySetInnerHTML`, keep that pattern but sanitize is not needed since backend output is trusted).
- For thread results, show: title, last activity date (formatted by existing `formatDate` helper), and tag dots / project badge (mirror the regular thread row metadata so users see which thread they are about to open).
- For task results, show: title, status badge, project name as subtitle.
- For project results, show: name, path as subtitle.
- Limit per section to 10 results in the UI; if backend returns more, show "+N more" link that opens the global SearchOverlay (the existing Cmd+K modal) prefilled with the same query.

## Behavior

- Selecting any result clears the search input and navigates (mirrors existing `handleSelectSearchResult`).
- Pressing Escape clears the search and returns focus to the input (existing behaviour).
- The cross-category navigation must work on both desktop and mobile sidebar variants (the function `searchResultsView` is reused).

## Implementation Notes

- The `globalSearch` API client is already exported from `frontend/src/api/client.ts`.
- The `GlobalSearchResults` type is in `frontend/src/types`.
- React Router's `useNavigate` must be added to `ThreadSidebar.tsx` if not already imported, OR navigation must be done via a prop callback to keep the component pure. Prefer the prop callback (`onNavigate?: (path: string) => void`) so the sidebar stays decoupled from the router; the `ChatPage` wires it to `navigate(path)`.
