# Always pass highest effort to Claude Code invocations

Explicitly pass `--effort high` to every Claude Code subprocess that does real work, so Botka always runs at the highest reasoning effort regardless of per-model default changes (Opus 4.8 defaults to `high`, but other models/versions may differ).

## Background

Botka shells out to the `claude` CLI rather than calling the Messages API directly. The CLI supports `--effort <level>` (verified in `claude --help`). Today Botka never passes it, so effort is left to the model's per-version default. We want highest effort guaranteed everywhere.

## Requirements

- Append `--effort high` to the CLI args built for **interactive chat** in `internal/claude/runner.go` and the pre-warmed session pool in `internal/claude/pool.go`.
- Append `--effort high` to the **autonomous task executor** args in `internal/runner/executor.go`.
- Append `--effort high` to the **cron job** runner args in `internal/runner/cron.go`.
- Do NOT add the flag to `internal/runner/keepalive.go` (trivial "pong" ping) or `internal/runner/failure_summary.go` (short haiku summary) — effort is wasted there.
- The flag must be present on every code path above, including the remote/Box invocation path (`internal/claude/remote.go`) if it wraps the same arg list.
- Existing tests must keep passing; update any arg-assertion tests to expect the new flag.
- `make check` must pass before completion.

## Implementation Notes

- Follow the existing `args = append(args, "--model", ...)` pattern in each file — add the effort flag right alongside it so it travels with every spawn.
- Hardcoding `high` is acceptable per the requested behavior ("always highest effort"); a config var is not required. If you add one for cleanliness, default it to `high` and document it in CLAUDE.md's env table.
- Do NOT deploy or restart the botka service — build and test only, then mark done and note deployment is needed.
