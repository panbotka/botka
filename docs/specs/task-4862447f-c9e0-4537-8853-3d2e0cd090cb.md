# Thread folders with hierarchical organization

Allow organizing chat threads into nested folders, with drag-and-drop reordering.

## Background

The thread list in the chat sidebar is flat and grows unmanageably as threads accumulate. Users want to group related conversations (per-project, per-topic, archive, scratch) into folders, including nested folders for finer organization.

## Requirements

- New `thread_folders` table: `id` (bigserial), `name` (text), `parent_id` (bigint, nullable, FK self-referential), `position` (int, for sibling ordering), `created_at`, `updated_at`.
- Add `folder_id` (bigint, nullable, FK) to `threads` — null means "root level".
- HTTP API:
  - `GET /api/v1/folders` — return the folder tree (nested) with thread counts per folder.
  - `POST /api/v1/folders` — create folder (`name`, `parent_id` optional).
  - `PATCH /api/v1/folders/:id` — rename, move (change `parent_id`), reorder (change `position`).
  - `DELETE /api/v1/folders/:id` — only allowed if folder is empty (no child folders, no threads); otherwise return 409 with a useful error.
  - `PATCH /api/v1/threads/:id` — gains optional `folder_id` field for moving a thread between folders.
- Cycle prevention: moving a folder under one of its descendants must be rejected with 400.
- Maximum nesting depth: 5 levels. Reject attempts to exceed.
- Frontend:
  - Sidebar shows folder tree with collapsible nodes; threads appear under their folder; root-level (folder_id=null) threads appear above all folders.
  - Drag-and-drop: threads between folders, folders into other folders, threads/folders within a parent for reordering.
  - Right-click / kebab menu on folder: Rename, New subfolder, Delete.
  - Persist collapsed/expanded state per folder in localStorage.
  - Visual cue for empty folders.
- Migration: existing threads remain at folder_id=null (root) — no automatic categorization.

## Implementation Notes

- The folder tree is small (tens of nodes typical) — fetch the entire tree in one query, build the tree in Go, and return as JSON. No need for recursive CTEs at the API layer.
- `position` is per-parent; on insert, set to `MAX(position) + 1` for the parent (or 0 if first child). On reorder, the frontend sends an explicit ordered list of child IDs and the backend assigns sequential positions.
- Cycle check: before saving a folder move, walk the proposed new ancestor chain and reject if the folder being moved appears in it.
- Counting threads in a folder for the badge: count direct children only, not transitive — keeps the query cheap and matches user intuition.
