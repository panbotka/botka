# Message action sheet on mobile

Chat message actions live in `frontend/src/components/MessageActions.tsx` (Copy and Hide on all messages, Edit on user messages, Regenerate on the last assistant reply) and appear on hover — which doesn't exist on a phone, the primary device (iOS PWA). The backend already supports forking a thread (see the fork handlers / `fork_thread` MCP tool and `ThreadForkBadges`), but there is no UI action to fork from a specific message.

## Requirements

- On mobile, long-press (~450ms) on any message bubble opens a bottom sheet with the actions available for that message:
  - Kopírovat (copies the message markdown; toast "Zkopírováno")
  - Upravit (user messages only — same behavior as the existing Edit)
  - Regenerovat (last assistant message only — same as existing)
  - Forknout odsud (any message — creates a new thread containing the history up to and including this message, using the existing fork backend; then navigates to the new thread)
  - Skrýt (same as existing Hide)
- The long-press must not trigger iOS text selection / callout (`-webkit-touch-callout: none`, `user-select: none` on the bubble during press) and must not fire if the finger moves (scroll) more than ~10px. Short taps keep working (links, images, code copy buttons inside the message).
- Light haptic feedback via `navigator.vibrate(10)` where supported.
- On desktop, keep the hover actions and add "Forknout odsud" to them as well.
- No hover-only actions are shown on mobile anymore (avoid duplicate invisible buttons).

## Implementation Notes
Check how the fork backend expects the fork point (message id) and reuse it; if the endpoint only forks a whole thread, extend it with an optional message id parameter that copies messages up to that one (non-soft-deleted only — remember `deleted_at IS NULL` in raw SQL) and add a Go handler test for it. Reuse a shared `BottomSheet` component if one exists in the codebase; otherwise create one. Vitest test: long-press opens the sheet with the correct actions per message type. `make check` must pass.
