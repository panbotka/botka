# Fix chat bubble flex min-content expansion

Previous fix (commit c0fbdf8) added `overflow-wrap: anywhere` to `.markdown-content` but chat messages still cause horizontal page scroll. Root cause: the message bubble div in `frontend/src/components/MessageBubble.tsx` is a flex item in a `flex flex-col items-start/items-end` wrapper and has no `min-w-0`, so its default `min-width: auto` expands the bubble to the content's min-content size, pushing it beyond the `max-w-[75%]` cap of the outer wrapper. The inner `overflow-hidden` clips the bubble's children but the bubble element itself is already wider than its parent, so the chat scroll container (`ChatView.tsx:782`, `overflow-y-auto` which implicitly enables `overflow-x: auto`) shows a horizontal scrollbar.

## Requirements

- In `frontend/src/components/MessageBubble.tsx`:
  - Add `min-w-0 max-w-full` to the bubble div (line ~296, the element with `rounded-2xl px-4 py-3 break-words overflow-hidden`).
  - Add `min-w-0 max-w-full` to the inner assistant text container (line ~344, `<div className="text-[15px]">`), and to the user `<p>` at line ~333 if needed.
- In `frontend/src/components/ChatView.tsx:782`, also set explicit `overflow-x-hidden` on `scrollContainerRef` as a safety net so no future bug reintroduces horizontal page scroll.
- In `frontend/src/components/TaskOutputView.tsx`, verify the text group wrapper (around line ~134, `<div className="prose prose-sm prose-zinc max-w-none min-w-0 break-words">`) does not allow horizontal overflow; add `max-w-full` and ensure parent container has `min-w-0` too.
- Verify bullet lists, numbered `SelectableOptions` items, long URLs, and inline code all wrap inside a 360px-wide viewport with no horizontal scrollbar on the page.
- Add a Vitest case that renders a `MessageBubble` with assistant content containing a 400-char unbroken string, mounts it at 360px wide, and asserts `scrollWidth <= clientWidth` on the scroll container.
- Do not remove `overflow-wrap: anywhere` — the two fixes work together.
- `make check` must pass.

## Implementation Notes

- CSS spec: when one `overflow` axis is not `visible`, the other axis is computed as `auto`. That is why `overflow-y-auto` on the scroll container enables horizontal scroll when children overflow. The explicit `overflow-x-hidden` prevents this.
- `min-w-0` on flex items overrides the default `min-width: auto` that would otherwise use the content's min-content width.
- Don't touch the bubble's `max-w-[85%] md:max-w-[75%]` cap on the outer wrapper — it's correct.
