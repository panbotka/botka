# Active Chat Tabs Bar

Show a tab-like bar at the top of the chat page listing threads that currently have an active Claude Code session, letting the user switch between them.

## Requirements

- Render a horizontal tab bar at the top of the chat page (above the message area) on all viewports where chat is used.
- Each tab represents a thread that currently has an active Claude Code session (i.e. a live entry in the chat session pool / registry, not merely a thread that exists in the DB).
- Tabs appear in the order they became active (order of opening); newly activated threads are appended to the right. Existing tabs do not reorder on focus.
- The currently viewed thread's tab is visually highlighted as active.
- Clicking a tab navigates to that thread's chat view without closing the session.
- The existing close (X) control on each tab continues to work unchanged — it closes/stops the session and removes the tab.
- When no threads have an active session, the bar collapses (no empty bar / no placeholder text taking vertical space).
- Tab labels use the thread title; long titles are truncated with ellipsis but full title is available on hover (title attribute).
- Bar reflects session state in near real-time — when a session starts elsewhere (e.g. another browser tab / SSE event) the new tab appears; when it ends, the tab disappears.
- Horizontal overflow: if tabs exceed viewport width, allow horizontal scrolling within the bar (no wrapping to multiple rows).

## Implementation Notes

- "Active session" state is derivable from the existing chat session registry / pool (`internal/claude/registry.go`, `internal/claude/pool.go`); expose or reuse the already-available list endpoint / SSE signal rather than inventing a new source of truth.
- Keep the "open order" client-side (React state) — server only needs to answer "which threads have active sessions right now".
- Reuse existing chat close/stop action for the X; do not duplicate it.
