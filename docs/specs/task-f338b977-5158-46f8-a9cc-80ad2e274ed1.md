# Box shutdown handler nesmí maskovat chybu jako úspěch

Handler pro vypnutí boxu vrací HTTP 200 „úspěch" i když SSH příkaz selže, takže selhání vypadá v UI jako úspěšné vypnutí.

## Requirements

- `BoxHandler.Shutdown` (internal/handlers/box.go, ~163–183) musí při selhání SSH příkazu vrátit **chybovou** odpověď (ne 200), s textem chyby a výstupem SSH.
- Odstranit/opravit stávající logiku (~171–177), která považuje běh za úspěšný, pokud jen nevypršel kontext — reálné selhání (např. `Permission denied`, `sudo: a password is required`, nenulový exit) musí vést k chybě.
- Speciální případ: když se spojení přeruší proto, že se stroj **skutečně vypíná** (očekávané zavření SSH při poweroffu), NEbrat jako chybu — odlišit od auth/permission selhání (které nastane rychle a bez zahájení vypínání).
- UI na chat.panbotka.cz/box musí při neúspěchu zobrazit čitelnou chybu (červené „shutdown selhal: …"), při úspěchu potvrzení jako dosud.
- Stejný princip aplikovat i na související akce, pokud sdílejí tu maskovací logiku (wake, start/stop service) — jinak je nechat být.

## Implementation Notes

- Root cause historicky: shutdown SSHuje jako `BOX_SSH_USER` a spouští `sudo shutdown now`; když auth/sudo selže, teď se to spolkne. Cílem je viditelnost selhání, ne změna mechanismu.
- Odlišení „stroj se vypíná" vs „auth selhalo" jde poznat podle rychlosti a textu chyby (permission/auth vs. přerušené spojení po zahájení shutdownu).
- Kontext: shutdown byl nedávno opraven (BOX_SSH_USER=panbotka + scoped /etc/sudoers.d/panbotka-shutdown na boxu); tahle úloha řeší jen viditelnost budoucích selhání, ne samotné vypínání.
