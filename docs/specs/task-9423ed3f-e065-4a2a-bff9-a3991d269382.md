
# Extend Search Backend Beyond Message Body

The chat sidebar search currently calls `/api/v1/search?q=...` which only matches against full-text indexed message body content. Users expect search to also find threads by title, by associated tag name, and by persona name. Without this, typing a known thread title returns no results, which feels broken.

## Requirements

- Extend `/api/v1/search/global` (handler returns `GlobalSearchResults` with `threads`, `tasks`, `projects`, `messages`) so the `threads` array matches against:
  - `threads.title` (case-insensitive substring)
  - Any tag name attached to the thread (case-insensitive substring on `tags.name`)
  - The persona name attached to the thread (case-insensitive substring on `personas.name`)
  - Existing message-body matching stays as-is and continues to populate the `messages` array
- Extend `/api/v1/search?q=...` (used by the sidebar — returns `[]SearchResult` with `thread` + `matches`) so it returns threads when the query matches:
  - Thread title (in addition to current FTS on message body)
  - Tag name attached to the thread
  - Persona name attached to the thread
- For title/tag/persona matches with no message match, return the thread with an empty `matches` array (frontend will render it as a thread-level hit). For message body matches, continue returning the existing snippet/highlight payload.
- Both endpoints must remain case-insensitive and tolerant of Czech diacritics (use Postgres `unaccent` if available, otherwise `ILIKE` is acceptable).
- Archived threads are still excluded by default (current behaviour) — do not change that.
- Limit and pagination semantics are unchanged.

## Implementation Notes

- Search handlers live in `internal/handlers/` (look for `search.go` or similar — grep for `SearchResult` and `GlobalSearchResults` types).
- GORM models for `Thread`, `Tag`, `Persona`, `Message` are in `internal/models/`.
- Postgres FTS GIN index is on the message tsvector column — leave it alone for body matching.
- For thread title / tag / persona name matching, plain `ILIKE '%' || query || '%'` is fine; the dataset is small.
- De-duplicate threads in the result: if a thread matches both via title and via a message, return it once with the message snippet included.

## Tests

- Add Go handler integration tests in `internal/handlers/` covering:

  - Search by tag name returns threads with that tag
  - Search by persona name returns threads with that persona
  - Search by query that matches message body still returns snippets
  - Combined match (title + body) returns thread only once
