# Full-text search across tasks

Add full-text search over task `title`, `spec`, and `failure_summary` fields.

## Background

The current task list supports filter-by-status and filter-by-project but no text search. Finding "that task about VAPID" or "the one that failed because of the typo in migrations" requires scrolling. Messages already use a `tsvector` GIN index — replicate that pattern for tasks.

## Requirements

- Add a `search_vector` `tsvector` column to the `tasks` table.
- Populate it from `title || ' ' || spec || ' ' || COALESCE(failure_summary, '')` via a Postgres trigger on INSERT/UPDATE so it stays in sync without app-side code.
- Create a GIN index on `search_vector`.
- Use `simple` text search config (not `english` / `czech`) since spec language is mixed and we want exact matches on technical terms.
- Extend `GET /api/v1/tasks` with `?q=<query>` parameter:
  - Empty / missing `q`: existing behavior unchanged.
  - Non-empty `q`: filter by `search_vector @@ plainto_tsquery('simple', ?)`, ordered by rank descending then by `created_at` desc as tiebreaker.
- Combine `q` with existing filters (status, project, tag) using AND semantics.
- Migration must backfill `search_vector` for existing rows.
- Frontend:
  - Add a search box at the top of the task list. Debounced 250ms.
  - Show search query in URL (`?q=...`) so search state survives reload.
  - When search is active, show a "Clear" affordance.
- MCP `list_tasks` tool gains an optional `query` parameter mirroring `q`.

## Implementation Notes

- Trigger function: `tsvector_update_trigger(search_vector, 'pg_catalog.simple', title, spec, failure_summary)`.
- Index: `CREATE INDEX idx_tasks_search ON tasks USING GIN (search_vector);`
- Reference implementation: see how `messages.search_vector` is wired in `migrations/` for the existing pattern — copy it.
- Backfill: `UPDATE tasks SET search_vector = to_tsvector('simple', coalesce(title,'') || ' ' || coalesce(spec,'') || ' ' || coalesce(failure_summary,''));` in the migration.
