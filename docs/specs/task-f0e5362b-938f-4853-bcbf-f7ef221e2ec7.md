# Fix Refresh button on update banner (SW skip-waiting message mismatch)

The "New version available" -> Refresh button does nothing on both mobile and
desktop after a new Botka version is deployed. The page never reloads to the
new version.

## Root cause (already diagnosed)

- `UpdateBanner.tsx` calls `updateServiceWorker(true)` from vite-plugin-pwa.
- With `strategies: 'injectManifest'`, that path ends in workbox-window's
  `messageSkipWaiting()`, which posts `{ type: 'SKIP_WAITING' }` to the waiting
  service worker.
- The custom worker `frontend/src/sw/sw.ts` only handles
  `data.type === 'skip-waiting'` (lowercase + hyphen), so the message never
  matches, `self.skipWaiting()` is never called, the new worker stays in the
  `waiting` state, `controllerchange` never fires, and the page never reloads.

## Requirements

- Update the `message` handler in `frontend/src/sw/sw.ts` to call
  `self.skipWaiting()` when it receives the message vite-plugin-pwa / workbox
  actually sends: `{ type: 'SKIP_WAITING' }`. (Keep any existing behavior for
  other message types such as `vapid-key`.)
- After clicking Refresh, the waiting worker must activate and the page must
  reload onto the newly deployed version — verified on both desktop and mobile.
- Confirm the fix end to end: build the frontend, load it, simulate a waiting
  worker / new version, click Refresh, and observe the reload to the new
  assets (document how it was verified in the task output).
- Do not break the existing push-notification, navigation, VAPID-key, or
  precache behavior in the service worker.
- `make check` must pass.

## Implementation Notes

- Match the exact string workbox uses (`SKIP_WAITING`, uppercase + underscore);
  accepting both the old and new strings is fine but the new one is mandatory.
- Because a service worker file itself must reach the browser to take effect,
  note in the output that users on a currently-broken worker may need one
  manual hard-reload for the corrected worker to install the first time.
