
# Thread Settings Side Panel

Per-thread settings (model, color, tags, sources, custom context, signal bridge, MCP servers) currently live inside the per-thread MoreVertical menu in the sidebar. This mixes settings with actions and crowds the menu. Move all per-thread settings into a dedicated side panel opened from the chat header.

## Requirements

- Add a "Settings" cog icon button in the chat header, to the right of the existing model badge (header is at `frontend/src/pages/ChatPage.tsx`, both desktop and mobile variants). Use the `Settings` icon from `lucide-react`.
- Clicking the cog opens a right-side slide-in panel that overlays the chat (similar visual style to existing modals in `ThreadSourcesEditor.tsx`). Panel is 380px wide on desktop and full-screen on mobile.
- Panel header shows: thread title, close button (X icon).
- Panel body contains the following sections, each as a clearly labeled group:
  1. **Persona** — read-only display of current persona name + icon (not editable here; persona is set on thread creation).
  2. **Model** — inline `ModelPicker` component (already exists at `frontend/src/components/ModelPicker.tsx`). Selecting a model calls the existing update-model API and updates state without closing the panel.
  3. **Color** — 4-column grid of color swatches from `THREAD_COLORS` (in `frontend/src/utils/threadColors.ts`). Click to set; the "no color" entry is the X swatch. Calls existing `api.updateThread(id, { color })`.
  4. **Tags** — list of all tags with checkbox-like circles (filled when assigned). Click to toggle. Calls existing `api.updateThreadTags(id, ids)`. If no tags exist, show "No tags created yet."
  5. **Sources** — button "Manage sources" which opens existing `ThreadSourcesEditor` modal on top of the panel.
  6. **Custom Context** — button "Edit custom context" which opens existing `CustomContextEditor` modal. Show character count badge if context exists.
  7. **Signal Bridge** — button "Configure Signal Bridge" which opens existing `SignalBridgeEditor` modal. Show a green "Active" badge if `thread.signal_bridge_active` is true.
  8. **MCP Servers** — button "Manage MCP servers" which opens existing `MCPServerToggle` component with `scope={ type: 'thread', id: threadId }`.
- Closing the panel is via: clicking X, pressing Escape, or clicking outside the panel (backdrop).
- The panel must reflect live thread state — when other components update the thread (e.g. user changes model from elsewhere), the panel reflects the new value. Use the `thread` prop passed in, do not fetch separately.
- Hide the cog button entirely when `user.role === 'external'` (read-only) or when no thread is active.
- Add the cog button only to the active-chat header — it is per-thread and only makes sense when a thread is selected.

## UI Details

- Use existing Tailwind tokens consistent with the rest of the app: `bg-zinc-50` panel background, `border-zinc-200` borders, `rounded-xl` for sections, `text-sm` for labels.
- Section labels: small, uppercase, `text-zinc-400`, like the sidebar's "Pinned" / "Archived" headers.
- Smooth slide-in animation (`animate-in slide-in-from-right` if available, otherwise plain `transition-transform`).
- Panel must scroll independently when content exceeds height.

## Behavior

- Open state is local to the page — closing and reopening returns to top of panel (do not persist scroll position across opens).
- All actions inside the panel call existing APIs and trigger `onThreadsChange()` so the sidebar reflects updates.
- Do NOT remove the menu items from `ThreadSidebar.tsx` in this task — that is a separate cleanup task. Both entry points coexist for now.
