# Show the task's current run phase instead of a bare "running"

A task sits at `running` for minutes after its commit has already landed, with nothing in the UI explaining what is still happening. Expose the executor's phase so the wait is legible.

## Background

`Executor.Execute` (`internal/runner/executor.go:85`) walks a fixed sequence:
`exists` → `syncSpec` → `setupBranch` → `spawnClaude` → `maybeVerify` → `pushAndCreatePR`.
Only `spawnClaude` is the Claude session. Verification (`make check` and friends) and the PR
push run afterwards and can take several minutes. Observed on task
`a629f14e-5377-4038-905b-ee8323056e7c`: commit at 23:16:05, `task finished status=done` at 23:19:08.

## Requirements

- Add a nullable `run_phase` column to `tasks` (migration + `models.Task` field + JSON tag).
  It is set only while `status = 'running'` and cleared on every terminal status.
- Phases, in order: `preparing` (spec sync + branch setup), `agent` (Claude subprocess),
  `verifying` (verification command), `publishing` (push + PR), `summarizing` (failure summary).
- `Executor.Execute` records each phase transition before entering that step. Recording a phase
  must never fail the task: on a DB write error, log a warning and continue.
- Phase changes emit an SSE event on the existing task stream so an open detail page updates
  without a refetch. Reuse the `task_status` event shape rather than inventing a new channel.
- The task detail page and the task list row render the phase next to the `running` badge
  (e.g. `running · verifying`). When `run_phase` is null, render exactly what is rendered today.
- A task that crashes or is killed mid-phase must not keep a stale `run_phase` — the runner's
  existing terminal-status write clears it.
- Every new user-facing string is Czech-first, matching how the rest of the UI reads.

## Verification

`make check` passes. Add Go tests covering (a) the phase sequence written during a successful
run, (b) `run_phase` cleared on `done`, `failed`, and `cancelled`. Update `CLAUDE.md` where it
describes the task-mode spawn path.
