
# Search Prefix Syntax

The sidebar search input currently runs only text-based search. Power users want to filter the thread list inline using prefixes like `proj:botka tag:work` instead of clicking the separate filter bar chips. Add prefix syntax that filters the existing thread list locally without changing the underlying API.

## Requirements

- Implement prefix parsing for the sidebar search input in `frontend/src/components/ThreadSidebar.tsx` (or extracted into a small helper file in `frontend/src/utils/`).
- Supported prefixes (all case-insensitive on both key and value):
  - `proj:<name>` — match threads whose project name (resolved via `projectMap`) contains `<name>` as a case-insensitive substring.
  - `tag:<name>` — match threads that have at least one tag whose name contains `<name>`.
  - `persona:<name>` — match threads whose persona name contains `<name>`.
  - `archived:true` / `archived:false` — include or exclude archived threads (overrides the current `showArchived` toggle for this query).
  - `pinned:true` / `pinned:false` — limit to pinned (or non-pinned) threads.
- Prefixes can be combined (whitespace-separated) and are AND-ed together. Free-text tokens that are not prefixes apply as a case-insensitive substring match against `thread.title` AND `thread.last_message_preview`.
- Quoted values are supported: `tag:"my tag"` so multi-word values work.
- When the search input contains ONLY prefixes (no free-text tokens), do NOT call the backend search API — filter the existing in-memory `threads` array and render the result inside the existing thread list view (with pinned/regular/archived sections, same `renderThread`).
- When the search input contains BOTH prefixes AND a free-text component, run the existing global search for the free-text part and then apply the prefix filters to the returned thread results client-side. Messages/tasks/projects in global search results are NOT filtered by prefixes (they are different entity types) — they appear under their headers as-is.
- Show a small inline "active filters" row above the result list when any prefix is active, listing them as removable chips (`tag: work ×`). Clicking the × removes that token from the input.

## UI Details

- The search input layout, debounce, clear-X, and escape behaviour stay the same.
- The active-filters row sits between the search input and the result list, only visible when prefixes are present in the parsed query.
- Use the same chip styling as the existing filter bar (`bg-zinc-200/60 border-zinc-300 text-zinc-800` for active).

## Edge Cases

- Unknown prefix (e.g. `foo:bar`): treat the entire token as free-text. Do not error.
- Empty prefix value (e.g. `tag:`): ignore the token.
- Multiple `proj:` tokens: AND them — a thread must match all (this is essentially impossible but stay consistent with AND semantics rather than crashing).
- `archived:true` with the global `showArchived` toggle off: the prefix wins for this query.
- Prefix matching is substring, not exact. `proj:bot` matches "botka" and "robot". This is intentional for ergonomics.
