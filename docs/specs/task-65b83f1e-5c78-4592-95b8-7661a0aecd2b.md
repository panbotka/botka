
# Slim Down Per-Thread Action Menu

The per-thread MoreVertical menu in `frontend/src/components/ThreadSidebar.tsx` currently has 12 entries which overwhelms users. Reduce it to the 5 most-used actions. Settings-type entries (model, color, tags, sources, custom context, signal bridge, MCP servers) have already been moved to a dedicated Thread Settings side panel in the chat header — those entries should be removed from this menu entirely.

## Requirements

- The MoreVertical dropdown for each thread row must contain ONLY these 5 actions, in this order:
  1. Pin / Unpin (toggle, with current label based on `thread.pinned`)
  2. Rename
  3. Archive / Unarchive (toggle, with current label based on `thread.archived`; current confirm dialog stays)
  4. Export
  5. Delete (with current confirm dialog, separated by a divider, red text)
- Remove the following entries from the menu and delete the related state, refs, handlers, and modal mounts that are now unused inside `ThreadSidebar.tsx`:
  - "Change model" entry and `modelPickerThread` state + `modelPickerModal` JSX (the `ModelPicker` component itself stays — it is reused in the new settings panel)
  - "Sources" entry and `sourcesThreadId` state + `<ThreadSourcesEditor>` mount
  - "Custom Context" entry and `customContextThread` state + `<CustomContextEditor>` mount
  - "Signal Bridge" entry and `signalBridgeThreadId` state + `<SignalBridgeEditor>` mount
  - "MCP Servers" entry and `mcpServersThreadId` state + `<MCPServerToggle>` mount
  - "Color" entry, the nested color grid, and `colorMenuThreadId` state
  - "Tags" entry, the nested tag list, and `tagMenuThreadId` state
- Remove the now-unused `lucide-react` icons from imports (Cpu, Globe, FileText, MessageSquare, Server, Plug, Palette, Tag — keep ones still used elsewhere in the file).
- Remove the now-unused `THREAD_COLORS` import if no longer referenced (it is still used to render the colored left border on thread rows — keep it for that).
- The thread row visual indicators (color border, persona icon, signal-bridge icon, tag dots, project badge) all stay — those are display, not menu actions.
- Keyboard interactions: Escape closes the menu (existing). No new shortcuts in this task.

## Edge Cases

- The Trash icon and divider for Delete stay; Delete remains the last item.
- Mobile and desktop sidebar variants both use the same `renderThread` function — both get the slimmed menu automatically.
- Read-only mode (`readOnly` prop) already hides the menu button entirely; keep that.

## Tests

- Update `frontend/src/components/ThreadSidebar.tsx` tests if any exist that assert on the removed menu entries.
- Add a test (Vitest) that opens the menu and asserts exactly 5 visible action buttons (Pin, Rename, Archive, Export, Delete).

## Verification

- `make check` must pass.
- The thread settings (model, color, tags, sources, custom context, signal bridge, MCP servers) must remain accessible somewhere — they are reachable via the cog/settings button in the chat header. If during implementation that entry point appears missing, STOP and add a TODO comment rather than restoring the menu items.
- Do NOT deploy or restart the systemd service.
