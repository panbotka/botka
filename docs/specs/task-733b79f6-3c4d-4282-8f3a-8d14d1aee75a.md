# Task detail: controls on top, readable timestamps

On the task detail page (`frontend/src/pages/TaskDetailPage.tsx`) the action buttons sit below the spec, notes, diff and live output, which can be very long — the user has to scroll to the bottom to queue, retry or kill a task. Also, in the stat cards (`frontend/src/components/TaskStatsCards.tsx`) the Started/Finished values are truncated so on a phone only the date is visible, not the time.

## Requirements

### Action bar
- Move all task action controls into one action bar placed directly under the header (title + status + meta line), above the stat cards. This includes: "Spustit teď" (force-run, queued only), Queue, Cancel, Retry, Mark Done, Restore, Delete, Edit, and Kill (running only — currently a separate block).
- Visibility rules per status stay exactly as they are today; only the placement changes. Delete keeps its confirmation.
- Order by importance: the primary action for the current status first and visually prominent (e.g. pending → "Do fronty", queued → "Spustit teď", running → "Kill" in red, failed/needs_review → "Retry"), then secondary actions, destructive (Delete) last.
- Mobile: the action bar is sticky at the top of the scroll container while scrolling through the long output; show the primary action + at most one secondary action as buttons, the rest in a "⋯" overflow menu. Buttons at least 44px tall.
- Desktop: the bar can show all buttons inline; sticky is fine too.
- Remove the old bottom button block and the separate Kill block so the actions exist in exactly one place.

### Timestamps in stat cards
- Started and Finished must always show the time. Format:
  - today → `14:32`
  - this calendar year → `17.10. 14:32`
  - older → `17.10.2025 14:32`
- Remove the truncation that hides the time; if the value still doesn't fit, let it wrap to two lines (date / time) instead of ellipsis.
- Full date-time with seconds as a `title` tooltip.
- Put the formatter in `frontend/src/utils/dateFormat.ts` with Vitest unit tests (today / this year / older, using a fixed "now").
- The grid may switch to fewer columns on narrow screens if needed to keep values readable (e.g. 2 columns on phone is fine, but nothing truncated).
