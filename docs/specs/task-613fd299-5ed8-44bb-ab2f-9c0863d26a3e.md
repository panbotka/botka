# Smaller frontend bundle for chat

The production build has two heavy chunks hurting first load on a phone:
- `CodeBlock` (~630 kB): `react-syntax-highlighter` full Prism build with every language, lazy-loaded but pulled in whole on the first code fence.
- The shared markdown chunk (~430 kB JS + 29 kB CSS, named after `ToolCallPanel`): react-markdown + remark-math/rehype-katex + KaTeX, with KaTeX CSS imported in `frontend/src/components/MarkdownContent.tsx`, which emits ~60 KaTeX font files (woff2 + woff + ttf).

## Requirements

- Switch `CodeBlock` to the `PrismLight` (or `PrismAsyncLight`) build and register only a curated set: bash/shell, go, typescript, tsx, javascript, jsx, json, yaml, sql, python, css, html/markup, markdown, diff, dockerfile, makefile, toml, ini, rust, nginx. Map common aliases (`sh`, `zsh`, `shell`, `ts`, `js`, `yml`, `golang`, `py`, `console`). Unknown languages render as plain preformatted code with the same styling (no crash).
- Load KaTeX only when needed: include `remark-math`/`rehype-katex` and the KaTeX CSS only for messages whose content actually contains math delimiters (`$$`, `\(`, `\[`, or inline `$…$` per the current remark-math settings). Do this via a lazily imported module so non-math messages never download KaTeX JS/CSS.
- Emit only woff2 KaTeX fonts (drop woff/ttf from the build output), e.g. via a CSS override or Vite asset handling, while math still renders correctly.
- Remove the unused `rehype-highlight` dependency from `package.json`.
- Everything that renders today still renders: code highlighting in chat and task output, math in chat.

- Add a Vitest test that a message without math does not render KaTeX markup and one with `$$x^2$$` does (async).
- `make check` must pass.
