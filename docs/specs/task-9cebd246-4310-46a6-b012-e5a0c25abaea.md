# Attach only files produced during the reply

After every chat reply, the backend scans the agent's tool traffic for anything that looks like a file path and attaches every match that exists on disk as a file card under the assistant message (`internal/handlers/chat_attachments.go` — `fromToolUse`, `fromToolResult`, the path regexes; capture loop in `internal/handlers/chat.go` around the `captureWrittenFile` calls). It regex-scans tool *results* too (`ls`, `find`, `grep`, file reads), and matches png/jpg/gif/webp/pdf/html/json/csv. A single `grep` over a repo can therefore attach dozens of files the agent merely read or listed. There is no count limit. The user sees a flood of irrelevant attachments.

## Requirements

- A path qualifies for capture only if the file was **created or modified during this reply**: its mtime is at or after the moment the reply started (record the turn start time when the Claude subprocess run for this message begins; allow ~2s clock slack).
- Path sources:
  - Keep: `file_path` of Write / Edit / MultiEdit / NotebookEdit tool calls.
  - Keep: paths appearing in Bash *commands* (e.g. `chromium --screenshot=/tmp/x.png`, `agent-browser screenshot /x.png`), subject to the mtime rule.
  - Keep: paths appearing in tool results, but ONLY subject to the mtime rule (this covers tools that print "saved to /path/x.png"); a file the agent merely listed/read is older than the turn and is skipped.
- Drop `.json` from the auto-capture extension list (JSON files are nearly always config/fixtures, not deliverables). Keep png, jpg/jpeg, gif, webp, pdf, html, csv.
- Skip paths inside `node_modules`, `.git`, `dist`, `build`, `vendor`, the Botka uploads directory itself, and the Claude context dir.
- Cap: at most 8 captured files per reply. If more qualify, keep the 8 most recently modified and log at info level how many were skipped.
- Existing dedup and the 500 MB size limit stay.
- User uploads are unaffected.
- Existing attachments in the DB are not touched (no migration).
