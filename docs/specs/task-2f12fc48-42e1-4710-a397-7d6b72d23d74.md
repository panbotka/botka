# Chat header bookmarks bar

Add a small app-level bookmarks bar to the chat header so the user can pin links that open in a new tab, each shown as favicon + page title.

## Requirements

- **Global, not per-thread.** Bookmarks are shared app-wide and appear on every chat. Persist them in a new `bookmarks` table (migration `040_bookmarks`): `id`, `url`, `title`, `favicon_url`, `sort_order`, timestamps.
- **Backend CRUD** under `/api/v1/bookmarks`: `GET` (list, ordered by `sort_order`), `POST` (create from a URL), `DELETE /:id`. Follow the existing handler/model/api-client conventions.
- **Auto-fetch metadata on create.** The client sends only the URL; the server fetches the page and extracts the `<title>` (fall back to hostname if missing) and a favicon URL (from `<link rel="icon">`/`apple-touch-icon`, else `/favicon.ico`, else a favicon service). Reuse the HTML-parsing approach in `internal/claude/fetcher.go` (`golang.org/x/net/html`). On fetch failure still save the bookmark with hostname as title and a default icon — never block adding.
- **Header UI** in `frontend/src/pages/ChatPage.tsx`, placed in the same header row as the thread title, `ProjectPicker`, and model badge. Each bookmark renders as its **favicon only**, with the page title as the hover `title` tooltip; clicking opens the URL in a **new tab** (`target="_blank"`, `rel="noopener noreferrer"`).
- **Add button:** a small `+` icon at the end of the bookmark list. Clicking prompts for a URL (small inline input/popover), then calls create and appends the new favicon on success.
- **Delete via right-click:** right-clicking a bookmark (`onContextMenu`, prevent default) opens a small context menu / confirm to delete it, calling `DELETE /:id` and removing it from the bar.
- **Mobile:** the bar must be visible on mobile too. Since the existing header row is already full, on narrow viewports render the bookmarks as a **separate second row** beneath the header instead of inline.

## Implementation Notes

- Both header layouts in `ChatPage.tsx` (desktop + mobile branches) need the bar; consider extracting a `BookmarksBar` component to avoid duplication.
- Metadata fetch should be time-bounded and tolerant of errors like `fetcher.go` already is (timeout, graceful failure).
- Favicon `<img>` should have an `onError` fallback so a broken icon still shows something (e.g. a generic globe/link icon).
