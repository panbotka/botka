# Bulk task operations in list view

Let users select multiple tasks and apply actions in one go.

## Requirements

- Task list page gains a checkbox per row and a header checkbox for select-all-on-page.
- When at least one task is selected, a sticky action bar appears at the bottom showing count and offering: change priority, change status (pending/queued/cancelled), change project, delete.
- Each bulk action confirms via modal before executing. Delete requires a typed confirmation (project name or task count).
- Backend endpoints: `POST /api/v1/tasks/bulk` accepting `{ ids: [...], action: "set_priority|set_status|set_project|delete", value: ... }`.
- Bulk endpoint validates each ID, applies the action atomically per task (transactional batch), and returns a per-ID result list (success/error).
- Selection persists across filter changes within the same page session but clears on navigation.
- Running tasks cannot have their status changed by bulk action — they're skipped with an error in the result list.

## Implementation Notes

- Reuse existing single-task handlers internally; the bulk handler iterates and aggregates results.
- Frontend should use optimistic updates with rollback on partial failure.
