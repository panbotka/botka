# Calmer tool-call display while streaming

While a chat reply streams, `frontend/src/components/ChatView.tsx` (around the streaming section) renders one bordered `ToolCallPanel` per tool call, ungrouped, above the streaming bubble — a long agent turn grows into a tall stack of panels. When the reply finishes, that stack is replaced by a single collapsed "N tool calls" toggle in `MessageBubble.tsx`, so the whole layout jumps. On a phone this feels clunky.

## Requirements

- During streaming, show ONE compact activity row in place of the panel stack: spinner + the current (latest, still-running) tool's name and a short one-line summary of its input (e.g. `Bash · make test`, `Edit · TaskList.tsx`, `Read · chat.go`, `WebFetch · example.com`), plus a muted counter "· 7 nástrojů". Long summaries truncate with ellipsis on one line.
- When no tool is currently running (model is writing text), the row shows the last tool in muted style without spinner, or is hidden if there were no tools yet.
- Tapping the row expands the full list of the turn's tool calls (reusing `ToolCallPanel`, each individually collapsed as today); tapping again collapses. Expanded state survives new tool events during the same stream.
- When the reply completes, the same row turns into the persisted "N tool calls" toggle at the same position with the same look — no layout jump. Use one shared component for the streaming and the saved state.
- Position: the row sits at the top of the assistant message (above text), both while streaming and after completion, so the text never moves when tools finish.
- Write a small pure helper that produces the one-line summary from a tool name + input (with sensible handling of Bash, Read, Write, Edit, Grep, Glob, WebFetch, WebSearch, Task/Agent, MCP tools `mcp__server__tool` → `server: tool`, unknown → name only), with Vitest tests.
- Auto-scroll behaviour must stay as is (stick to bottom only when the user was near the bottom).

`make check` must pass.
