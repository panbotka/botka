# Recurring task schedules

Allow users to define cron-like schedules that auto-create tasks on a recurring basis.

## Requirements

- New `task_schedules` table: `id`, `project_id`, `title`, `spec`, `cron_expression`, `priority`, `enabled`, `last_run_at`, `next_run_at`, timestamps.
- A background goroutine in the runner package wakes every minute, finds enabled schedules with `next_run_at <= now()`, creates a task in `pending` status with the schedule's spec/title/priority, then computes the next `next_run_at` from the cron expression.
- API endpoints: `GET/POST /api/v1/schedules`, `GET/PUT/DELETE /api/v1/schedules/:id`, plus `POST /api/v1/schedules/:id/run-now`.
- New "Schedules" page in the frontend listing schedules with enable/disable toggle, next-run time, and edit/delete actions. Form supports cron expression with a human-readable preview.
- Created tasks reference the schedule via `schedule_id` foreign key on `tasks` (nullable). Task detail page shows "Created by schedule: <title>" link when set.
- Cron parser must support standard 5-field expressions including `*/N`, ranges, and lists.

## Implementation Notes

- Use a maintained Go cron library (e.g. `github.com/robfig/cron/v3`) for parsing/scheduling math; do not run its scheduler — just compute next-fire times.
