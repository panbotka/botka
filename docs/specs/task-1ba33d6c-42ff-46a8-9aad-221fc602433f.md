# Task Diff Viewer

Show the git diff produced by a completed task on the TaskDetailPage so the user can review changes without leaving Botka.

## Context

Tasks already store `BaseCommitSHA` and `HeadCommitSHA` on the `tasks` table (migration 024). When a task runs, the executor records the project's HEAD SHA before and after execution. The diff between these two SHAs represents what the task changed.

Some projects use `feature_branch` strategy (a `botka/task-<uuid>` branch is created and a PR may exist), others commit directly to main. The diff endpoint must work for both — use the recorded SHAs, not the current branch state. No GitHub API integration required — purely local git.

## Requirements

### Backend

- Add `GET /api/v1/tasks/:id/diff` endpoint that returns the unified git diff between `BaseCommitSHA` and `HeadCommitSHA`.
- Run `git diff <base_sha>..<head_sha>` via `os/exec` in the project's working directory.
- Response shape: `{"data": {"diff": "<unified diff text>", "stats": {"files_changed": N, "insertions": N, "deletions": N}, "truncated": false}}`.
- Compute stats with `git diff --numstat <base>..<head>` (sum insertions/deletions; count files).
- Return 404 if task does not exist.
- Return 200 with `{"diff": "", "stats": {files_changed: 0, insertions: 0, deletions: 0}, "truncated": false}` if either SHA is null (task hasn't run yet, or was cancelled before producing commits).
- If a SHA does not exist in the repo (`git cat-file -e <sha>` fails), return 404 with `{"error": "commit not found in repository"}`.
- Cap diff size at 5 MB. If exceeded, truncate at 5 MB and set `"truncated": true`.
- Auth: same middleware as other task endpoints (require authenticated user).
- Add handler tests in `internal/handlers/` covering: success, missing task, missing SHAs, missing commits, truncation flag.

### Frontend

- Add a "Changes" collapsible section on `TaskDetailPage` (`frontend/src/pages/TaskDetailPage.tsx`), visible when task status is `done`, `needs_review`, or `failed` AND both `base_commit_sha` and `head_commit_sha` are present.
- Place the section between Spec and Output (above the Output section).
- Header: `<N> files changed · +<insertions> −<deletions>`. Click to expand the section. Lazy-load the diff: only fetch when the user expands.
- Each file in the diff renders as a collapsible block similar in style to the existing `DiffView.tsx` component (font-mono, emerald for additions, red for deletions, +/− gutter).
- Parse the unified diff client-side into per-file blocks. Split on `diff --git`, then split file content on `@@ ... @@` hunk headers, classify each line by leading char (`+` add, `-` remove, ` ` context, `\` no newline marker).
- File header shows: short file name (basename), full path on hover/title attr, +/− counts per file.
- If `truncated: true`, render a banner above the file list: "Diff too large — only first 5 MB shown".
- Add an API client method in `frontend/src/api/client.ts` such as `fetchTaskDiff(id)`.

## Edge Cases

- Both SHAs equal (no commits): show "No changes" empty state inside the expanded section.
- Binary file change: show "Binary file changed" placeholder, no content (detect via `Binary files ... differ` line in diff output).
- Very wide lines (>2000 chars): wrap with `whitespace-pre-wrap break-all` (consistent with `DiffView.tsx`).

## Implementation Notes

- Backend: keep parsing minimal — pass through unified diff verbatim, stats come from `--numstat`. Do not pull in a Go diff library.
- Frontend: do not pull in a heavy diff parsing library; line-by-line parser is sufficient.
- Reuse colour and font-mono Tailwind classes from `frontend/src/components/DiffView.tsx` for visual consistency. You may either extract a shared sub-component or duplicate styling — keep `DiffView.tsx` working unchanged for tool-call diffs.
