
# Consolidate Filter Bar and New-Chat Persona Dropdown

The sidebar in `frontend/src/components/ThreadSidebar.tsx` currently has three separate UI affordances that overlap in function: a horizontal scrolling filter bar of tags+projects above the thread list, two side-by-side header buttons (`+` for new chat and `chevron` for persona picker), and an "Archived" toggle in the footer. This wastes vertical space and duplicates functionality that the new search prefix syntax already covers. Consolidate.

## Requirements

- **Remove the standalone filter bar** (`filterBar` variable in the file) entirely. Tag/project filtering is handled by the search prefix syntax (`tag:` / `proj:`) and by clicking entities elsewhere — do not maintain two parallel filter UIs.
  - Delete the `selectedTagIds`, `selectedProjectId`, `onToggleTagFilter`, `onClearTagFilter`, `onSelectProject` props from `ThreadSidebar` and from the parent `ChatPage.tsx`. They are no longer used.
  - Update `matchesFilters` accordingly — its tag/project logic goes away. It can be removed if nothing else uses it.
- **Merge the two header buttons** (`+` and persona-chevron) into a single split-button:
  - Primary click on the button starts an empty new chat (same as today's `onNewThread()`).
  - A small chevron-down attached to the right of the primary button (visually one combined control, not two separate buttons) opens the persona dropdown when clicked.
  - The dropdown content is unchanged: "Empty chat" entry on top, divider, then list of personas.
  - Visual: primary button has the `+` icon and label "New" (or icon-only on narrow widths). Chevron is a thin vertical-divider-separated section of the same pill.
  - If `personas.length === 0`, hide the chevron — show only the `+` button.
- **Keep the "Archived" toggle in the footer** — it stays as is. (The `archived:true` prefix is an alternative; the toggle is the discoverable default.)
- The mobile layout must mirror these changes — it currently renders the same `searchInput` + `filterBar`. Remove the filter bar there too.

## UI Details

- The split-button uses the existing pill styling. Primary part: `Plus` icon, label "New", `bg-amber-500 hover:bg-amber-400 text-white` (echo the FAB amber accent so the New action stands out). Chevron part: same background, slightly darker on hover, left border to separate visually.
- Mobile FAB (the floating amber circle for new chat) stays — it is the mobile-preferred entry point and not in conflict with this header change.

## Behavior

- Existing keyboard-shortcuts (the `useKeyboardShortcuts` hook) for "new chat" continue to work unchanged.
- Removing tag/project filter props from the sidebar must not break `ChatPage.tsx` — clean up the now-orphaned state (`selectedTagIds`, `selectedProjectId`) and props in that file too.

## Edge Cases

- If a saved/cached query string in the URL referenced filter selections, drop them — there is no migration concern.
- Read-only mode (`readOnly` prop): hide the entire split-button (matches current behaviour where buttons are hidden for `readOnly`).

## Tests

- Add a Vitest test that the split-button primary click triggers `onNewThread()` with no persona id, and chevron click opens the persona menu, and selecting a persona calls `onNewThread(personaId)`.
