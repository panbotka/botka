## Implementation Notes

- Failure root cause: `subscribe()` correctly sets `state='denied'` after `requestPermission()` returns `'denied'`, but its catch block then calls `computeState(devices)` which reads `Notification.permission`. The test mock doesn't update `Notification.permission` when `requestPermission()` resolves with `'denied'`, so `computeState` returns `'unsubscribed'` and overrides the explicit 'denied'.
- Two viable fixes — pick the cleaner one:
  1. Update the test mock so `requestPermission()` resolving with `'denied'` also updates the mocked `Notification.permission` to `'denied'` (mirrors real browser behavior).
  2. Have the hook preserve an explicit `'denied'` state through its catch (don't recompute if state was just set by the failure path).
- The first option is more honest — the test was broken, not the hook. Apply that one.
